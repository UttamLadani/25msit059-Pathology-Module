# 25msit059-Pathology-Module

Fieldnote Pathology is a small workflow demo: configure tests, create patient lab orders, and enter/view completed results. The UI is Angular; the API is Spring Boot + Spring Data JPA; MySQL persists the data.

## Requirements

- Java 17 or newer
- Node.js 20.19+ or 22.12+
- Docker Desktop with Compose for the MySQL setup

## Run locally

1. Start MySQL from the project root: `docker compose up -d mysql`
2. Start the API from `backend`: `./mvnw spring-boot:run` (PowerShell: `./mvnw.cmd spring-boot:run`; API at `http://localhost:8080`). The wrapper downloads Maven automatically; a global Maven install is not required.
3. In another terminal, start Angular: `cd frontend`, `npm install`, then `npm start` (UI at `http://localhost:4200`).

Default local database credentials are `pathology` / `pathology` and database `pathology`. Override with `DB_URL`, `DB_USER`, and `DB_PASSWORD`. Hibernate creates/updates tables for this demo; use migrations and externalized secrets before production.

To run the API without Docker/MySQL for a quick in-memory demo, start it from `backend` with `./mvnw spring-boot:run -Dspring-boot.run.profiles=demo` (PowerShell: `$env:SPRING_PROFILES_ACTIVE='demo'; ./mvnw.cmd spring-boot:run`). Demo-profile data resets when the API stops. If the UI says it cannot reach the pathology service, make sure this API process is running on port 8080.

## Workflow

1. Add tests in **Test Master**. Test codes are unique (case-insensitive at the API boundary), and name search filters the catalog.
2. Create an order in **Test Orders** by entering patient details, selecting a configured test, and choosing an order date. An order number is generated by the API. The list shows orders for the selected date, defaulting to today.
3. Open a pending order in **Result Entry**, enter the result and optional technician note, then save. The order becomes **Completed**; select a completed order to view its saved result and notes.

## API

- `GET /api/tests?search=` and `POST /api/tests`
- `GET /api/orders?date=YYYY-MM-DD` and `POST /api/orders`
- `PUT /api/orders/{id}/result` and `GET /api/orders/{id}/result`

The result endpoint only returns a report after completion. This demo intentionally omits authentication, patient records beyond the order, audit history, and PDF export.
